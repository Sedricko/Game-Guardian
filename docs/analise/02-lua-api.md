# 02 — API Lua `gg.*`, fork do LuaJ, LASM e documentação oficial (GameGuardian 101.4)

Escopo: camada de scripts do GameGuardian (GG) 101.4, build 16155. Base: código decompilado em
`src/sources/android/ext/Script.java` (5914 linhas), `src/sources/luaj/**`, `src/sources/lasm/**`,
`src/sources/g/h.java` (compilador) e a ajuda HTML oficial (`apk/res/raw/ydwhe`, descompactada em `help/`,
convertida para texto em `helptxt/`).

Convenção: **[C]** = confirmado no código/doc citado; **[H]** = hipótese (inferência razoável, não verificada até o fim).
Os caminhos abaixo são relativos a `src/sources/`, salvo indicação.

## 0. Resumo da arquitetura de scripts

```
arquivo .lua/.lasm ──► Globals.P3 (luaj/Globals.java:181)
                        ├─ "\x1bLua" → undumper luaj/a.java (bytecode Lua 5.2 + extensões)
                        ├─ "; --[=========[ Lua assembler file generated by GameGuardian " → lasm.a (assembler)
                        └─ texto → compilador g/h.java (sintaxe Lua 5.3)
             │
ScriptThread ("Script thread", Script.java:796) executa o chunk
             │  chamada gg.xxx(...)
             ▼
ApiFunction.invoke (Script.java:297) → b3(): posta Runnable na UI thread (n2.i) e BLOQUEIA (W3/wait)
             │                         → c3(): lógica real na UI thread
             ▼
MainService.instance (estado da UI, listas) e MainService.instance.i (= android/ext/f0, cliente IPC do daemon)
             │  comandos binários InOut.q(seq, cmd, len)
             ▼
daemon nativo (root/ptrace)  ──► resposta assíncrona com o mesmo "seq" → Script.c3(byte, String) (Script.java:5619)
```

- **[C]** Toda função `gg.*` herda de `ApiFunction extends VarArgFunction` (Script.java:117). `b3()` (Script.java:227)
  posta um Runnable na thread de UI (`n2.i`) e espera em `this.V` (`Script.W3`, Script.java:5177). Logo **a API é
  síncrona para o script, mas toda execução real acontece na UI thread** do GG.
- **[C]** Funções que dependem do daemon estendem `BusyApiFunction` (Script.java:395): o monitor de espera passa a ser
  o próprio objeto `Script`; o daemon responde via `Script.c3(byte seq, String msg)` (Script.java:5619), que confere
  o id do script e a sequência e faz `notifyAll()`. A string recebida (`l0`) vira o retorno de erro; se for `null`,
  o retorno padrão é `true` (`a3()` → `LuaValue.f1672d` = TRUE).
- **[C]** Número de sequência: `t3()` (Script.java:5838) = `20 + idScript*20 + (contador % 20)` em 1 byte; `idScript`
  = `n0 % 5` (Script.java:4935). Permite casar respostas do daemon com a chamada certa e descartar respostas velhas
  ("callNotify seq mismatch").
- **[C]** Argumento string > 1.000.000 caracteres no 1º parâmetro é truncado (Script.java:303).
- **[C]** Só um script por vez: `MainService.x()` (MainService.java:4293) para o anterior (`P()` → `w3()`), e o diálogo
  de execução pergunta antes de substituir (o0.java:104-110).

## 1. Referência completa da API `gg.*`

Registro de tudo em `Script.call()` (Script.java:5647-5790). A tabela `gg` é posta em `_G.gg` **e** em
`package.loaded.gg` (Script.java:5755-5756). As assinaturas abaixo vêm das strings `k3()` de cada classe (que o GG
usa para gerar a lista de API na UI e o log de depuração) e conferem com `help/classgg.html`.

Convenção de retorno herdada do GG: muitas funções retornam **`true` ou uma string com o erro** (nunca lançam erro
para falhas "esperadas"). Erros de argumento (tipo errado, `TYPE_*` inválido) lançam `luaj.d` (erro Lua).

### 1.3 Formato de item e conversões

- Chaves dos itens: `address, value, flags, name, freeze, freezeType, freezeFrom, freezeTo` (array `t0`, Script.java:92).
  `getResults/getValues` devolvem só as 3 primeiras; listas salvas devolvem as 8 (`o3`, ~5289).
- **[C] `TYPE_XOR` = valor XOR endereço**: `Q3` faz `j2 ^= address` ao ler e `q3` faz o mesmo ao escrever (5108, 5375).
- **[C]** Em alvo 32-bit o endereço é mascarado com `& 0xFFFFFFFF` (`T3`, 5130).
- **[C]** Valor como string passa por `D3` (número→locale do GG) e por `i2.x` (sufixo `X<n>` = distância da chave XOR,
  1..4096, i2.java:422) e então `c.e(addr, str, type)` (parser comum à UI: hex `h`, big-endian `r`, fórmulas etc.).

### 1.4 Sintaxe de texto de busca (help.html + i2.java) [C]

- Número simples (`10`), intervalo `10~20`, fora do intervalo `10~~20`, grupo `a;b;c[:tam]` (2-64 valores, tamanho
  padrão 512, máx. 65536), grupo ordenado `a;b::tam`, curinga posicional `0~~0`, sufixos de tipo por valor
  (`195D;6543`; `B W D X Q F E A`), hex LE `BAADh`, hex BE `BAADr`, XOR `100X8` (também com intervalo), texto
  `:utf8`, `;utf16le`, `h DF 59 ..`, `Q DF 'utf8' "utf16" 00`, opcode ARM `~A MOV R1, R2`.
- Busca "unsigned" automática: `<=`/`>=` com bit de sinal setado vira intervalo (`~0`/`~-1`) (i2.java:204-218).
- **Scripts sempre usam locale inglês** (`.` decimal, `,` milhar) — `scripts_locale.html`.

### 1.5 Recursos ligados à API que valem conhecer

- **[C] Gravador de scripts**: `MainService.f216f` (classe `c2`) escreve chamadas `gg.searchNumber(...)`,
  `gg.refineAddress(...)`, `gg.clearResults()` equivalentes a ações feitas na UI (i2.java:268-290, m1.java:46-60).
  O `Consts` (Script.java:420) converte máscaras em nomes (`gg.TYPE_DWORD | gg.TYPE_FLOAT`).
- **[C] Calculadora de fórmulas** (`= 2+2*3` em campos da UI): `Script.F3` (5044) cria um `Globals` separado com
  Base/Bit32/Table/String/Utf8/Math/Os (sem `gg`, `io`, `debug`, `package`) e executa `return <expr>` em modo `"t"`.

## 2. Fork do LuaJ

### 2.1 Versão da linguagem

- **[C] Sintaxe Lua 5.3** (inteiros, `//`, operadores bit a bit) compilada para **bytecode Lua 5.2** com opcodes extras
  `IDIV, BNOT, BAND, BOR, BXOR, SHL, SHR` após `EXTRAARG` (tabela de nomes em luaj/g.java:20). Compilador:
  `g/h.java` (`h.M(globals)` instala compilador e "loader", g/h.java:73).
- **[C]** Tipos numéricos `LuaLong` (inteiro) e `LuaDouble`. O undumper aceita uma tag de constante não padrão
  **`-2` = inteiro** (luaj/a.java:183), além de `0 nil, 1 bool, 3 number, 4 string` — bytecode do GG pode não rodar
  em Lua 5.2 oficial.
- **[C] Diferenças documentadas** (lua_details.html): biblioteca `coroutine` ausente (confirmado: `u3()` em
  Script.java:5428 carrega Base, Package, Bit32, Table, String, Utf8, Math, IoLibSafe, OsLibSafe, Debug — nada de
  Coroutine); `bit32` e funções 5.2 (ex. `math.pow`) presentes; **o 1º operando define o tipo do resultado**
  (`3/2.0 == 1`, `2.5+3 == 5.5`); `__gc` não funciona; `collectgarbage` é só dica (`System.gc()`, BaseLib.java:310).
- **[C]** `K3()` (Script.java:5087) zera metatabelas globais de nil/number/boolean/function/thread e recria a de
  string apenas com `__index=string`, antes e depois de cada execução — evita vazamento de metatabelas entre scripts.

### 2.2 Sandbox

Mecanismo central: `Script implements luaj.lib.e` com `m(String path, boolean readOnly)` (Script.java:5797) — retorna
`true` = **proibido**. Regras [C]:

1. Caminho dentro de `FILES_DIR/<hidden-dir>` (`Tools.q0()` = `files/` + `s0()`, um diretório aleatório salvo em
   preferências `"hidden-dir"`; Tools.java:3113/3220) → proibido (leitura e escrita).
2. Dentro de `CACHE_DIR/<hidden-dir>` (`Tools.c0()`) → proibido.
3. Se o caminho pedido é **pai** do arquivo de preferências do GG (`x2.g(MainService.G0)`, `<pkg>_preferences`) →
   proibido (impede apagar/renomear o diretório que o contém).
4. Em escrita (`readOnly=false`): o **próprio arquivo do script** é protegido (o script não pode se reescrever).
- Normalização: `getCanonicalPath` + `/data/data/` → `/data/user/0/` (luaj/lib/d.java:43), e, depois de abrir, o
  descritor é conferido via `readlink(/proc/self/fd/N)` (d.java:17-27, 95-115) — bloqueia truques com symlink/TOCTOU.

Aplicação:
- **`IoLibSafe`** (Script.java:532): `H3(path, mode)` → se proibido, abre um **arquivo vazio temporário** (`empty.txt`
  criado e apagado) em vez de falhar — o script "lê nada"/"escreve no vazio" silenciosamente.
- **`OsLibSafe`** (690): `os.remove`/`os.rename` em caminho proibido viram **no-op silencioso**.
- `loadList`/`saveList`/`saveVariable` usam `luaj.lib.d.e/f` com o mesmo `m()`.
- **Bloqueados com erro**: `os.execute` ("disabled by security reason", OsLib.java:114), `io.popen` (IoLib.java:1081),
  `package.loadlib` ("dynamic libraries not enabled", PackageLib.java:65), `stdin` ("stdin not supported").
- `os.getenv` funciona (OsLib.java:128). `debug.*` completo disponível (só logado).
- **Limites de recurso** (luaj/Globals.java): no máximo **1024 arquivos abertos** (`L3`, :108) e **1 GiB escrito no
  total** por execução (`M3`, :116). Ao final o GG informa "The script wrote X to N files" (Script.java:924).
- Rede só via `gg.makeRequest` com consentimento (§2.6). Não há `socket`.

### 2.3 Carregamento de scripts

`Script.M3()` (Script.java:5475) [C]:
1. `Globals.T3(dirDoScript)` → `require`/`dofile` relativos ao diretório do script (Globals.R3).
2. `Globals.O3(stream, "@"+path, "bt", G)` → `P3` (Globals.java:181):
   - 4 primeiros bytes `1B 4C 75 61` (`\x1bLua`) → undumper `luaj/a.java`.
   - Primeiros 61 bytes == `"; --[=========[ Lua assembler file generated by GameGuardian "` → **assembler LASM**
     (`lasm.a(...).u()`), Globals.java:223.
   - Caso contrário → compilador de texto (com remoção de BOM UTF-8, `Globals.c`).
3. Se o resultado veio do assembler (`proto instanceof lasm.b`), **não executa**: grava `<script>.<timestamp>.lua`
   (binário) + conteúdo de `<script>.tail`, e mostra "Successfully assembled to file:" (5496-5517).
4. Opções do diálogo "Executar script → Mais" (o0.java:80-96; flags em `Script.X`):
   - `1` = **desmontar** para `<nome>_<ts>_<rnd>.lasm` (+ `.tail`) antes de rodar (5537-5550);
   - `2` = **registrar todos os chunks passados a `load()`** em `<nome>.load` (um arquivo tar com `load_0000000.lua`…,
     BaseLib.java:201-245) — ótimo para desofuscar scripts que fazem `load(decrypt(...))`;
   - `4` = **log de chamadas** `gg.*`/`io`/`os`/`debug` em `<nome>.log.txt`, incluindo retornos de diálogos,
     contagem de `getResults` e "found:" das buscas (Script.java:297-360, 4880-4905).
5. Saída de `print` vai para `ScriptPrintStream` → `Logger` (arquivo temporário anônimo; ao final mostra no máx.
   os últimos 256 KiB, Script.java:578-675) num diálogo "Script ended:", com botão para re-executar.

### 2.4 Scripts binários, "Damaged script" e "cifragem"

- **[C] Não há cifragem própria do GG** no loader: um `.lua` é texto ou bytecode Lua 5.2 (+ extensões). A "proteção"
  usada pela comunidade é compilar para binário (amostra oficial "Script compiler", official_lua_samples.html) e/ou
  ofuscar com `load()` — que o GG intercepta com a flag 2.
- Validação de cabeçalho (`luaj/a.java:g()`, :244-340): versão `0x52`, formato 0, endianness 0/1, `sizeof(int)=4`,
  `sizeof(size_t)=4`, `sizeof(Instruction)=4`, `lua_Number` 4 ou 8; depois `LUAC_TAIL = 19 93 0D 0A 1A 0A`
  (:19, :330-339, erro "Unexpected byte in luac tail of header"). Se algo difere: diálogo "Invalid binary script
  header… In future versions of GG this script cannot be run" com link (cifra de César −3) para
  `gameguardian.net/forum/topic/26111-binary-scripts-with-corrupted-or-invalid-headers/` — e os botões
  Sim/Não são **trocados aleatoriamente** (`Tools.f489a.nextBoolean()`, a.java:~70) para impedir clique automático.
  Na 2ª vez (flag `u`) só mostra toast e continua.
- `int size` aceita 0, 1 ou 4 (`o()`, a.java:~120 — "unsupported int size").
- **"Damaged script"** [C]:
  - `Damaged script 2: .maxstacksize (X) < .numparams (Y)` — ao desserializar o protótipo (a.java:239);
  - `Damaged script: .maxstacksize < .numparams` — ao criar a closure (LuaClosure.java:232);
  - `Damaged script N: an attempt to get an upvalue with index I when there are T in total.` (LuaClosure.java:222).
  São defesas contra bytecode adulterado por ofuscadores (que costumam quebrar invariantes para travar decompiladores).
- **[C]** Mensagens de ajuda após erro (`ScriptThread.run`, 840-900): se a mensagem contém `<!DOCTYPE`/`<html`
  → "parece que você está executando uma página web como script"; se o arquivo parece uma lista salva (`z3`, 5861:
  1ª linha inteiro e linhas com ≥10 campos `|`) → "…uma lista salva como script". Erros do LASM mostram a linha
  com marcador (`LasmBase.c`).

### 2.5 Threading e interrupção

- **[C]** `ScriptThread` (Script.java:796), nome "Script thread", registrado em `n0.g` (handler de exceções).
- **[C]** Parar script: `x3(motivo)` (5850) seta `f0` e chama `Thread.interrupt()`. A interrupção só é percebida em
  pontos de espera: `W3` (todo `gg.*` bloqueante) e `gg.sleep`, que convertem `InterruptedException` em `luaj.d`;
  `ScriptThread` mostra "The script interrupted. [motivo]". Motivos vistos: 1 = usuário, 2 = abuso de
  `setVisible`, 3 = abuso de `processKill`.
- **[H]** Não achei checagem de interrupção no laço do interpretador (`LuaClosure`, sem `Thread.interrupted`): um
  `while true do end` sem chamadas `gg.*` provavelmente não para de forma limpa.
- **[C]** Como toda chamada `gg.*` faz *round-trip* pela UI thread, chamadas em laço apertado são caras; o padrão
  oficial de botão é `while true do if gg.isClickedUiButton() then ... end gg.sleep(100) end`.

### 2.6 `gg.makeRequest` (Script.java:3007-3268) [C]

- Na 1ª chamada por execução: diálogo "The script wants to access the Internet. If you allow access, the script will
  be able to steal your logins, passwords…" (`script_prompt_internet`); a decisão fica no campo `e0` da instância
  (vale para a execução inteira; recusa → retorna `"The user did not allow access to the Internet."`).
- `HttpURLConnection`; timeouts 30 s (connect/read) e 30 s para o upload do corpo POST numa thread
  `PostWriteWorker` (711); `data ~= nil` ⇒ POST com `Content-Type: application/x-www-form-urlencoded` e
  `Content-Length` padrão; headers aceitam string ou lista.
- Corpo limitado a **16 MiB** (checa `Content-Length` e bytes lidos). Em erro HTTP lê `getErrorStream` e seta
  `error=true`.
- Retorno: `url, requestMethod, code, message, headers{nome={...}}, contentEncoding, contentLength, contentType, date,
  expiration, lastModified, usingProxy, cipherSuite, content` (bytes crus como `LuaString`).

### 2.7 Botão de UI do script

- `showUiButton/hideUiButton` → `MainService.R0(bool)` posta a criação/remoção de uma view flutuante (`f214d`);
  clique → `f215e = true` (MainService.java:3795); `isClickedUiButton` lê e zera. Não há callback: é *polling* [C].

### 2.8 Anti-tamper dentro da API (relevante só para entender comportamento estranho)

- **[C]** No código do `gg.prompt` há 8 cópias de uma checagem: se o APK do GG foi instalado há mais de
  82.152.849 ms (~22,8 h) **e** um texto da UI não começa com o rótulo esperado + `f0.a0()` (info do daemon), agenda
  `_G["gg"]["searchNumber"] = nil` (strings cifradas com César −3: `"jj"`→`gg`, `"vhdufkQxpehu"`→`searchNumber`,
  `Tools.removeNewLinesChars`, Tools.java:3194) — Script.java:3648-3962.
- **[H]** Objetivo: quebrar silenciosamente builds repacotados/modificados. Detalhes de proteção ficam no relatório
  de proteção.

## 3. LASM (Lua assembler do GG)

**O que é** [C] (lasm.html + código): disassembler/assembler textual do bytecode Lua 5.2 do GG, para *pequenas
edições* em scripts binários (não para escrever do zero).

- Disassembler: `luaj/g.java` (`A()` :43) — imprime cabeçalho
  `; --[=========[ Lua assembler file generated by GameGuardian 101.4 (16155)` e rodapé
  `; ]=========] gg.require('101.4', 16155)` (o arquivo .lasm é, ao mesmo tempo, um script Lua válido que só exige
  a versão!). Dados após o fim do chunk vão para `.tail` (`g.M`, :839).
- Assembler: `lasm/a.java` (parser gerado, 1164 linhas, `extends LasmBase implements e.a`), `lasm/b.java` (protótipo
  montado, `extends luaj.h`), `lasm/LasmBase.java` (conversões, mensagens de erro com linha/coluna).
- Sintaxe:
  - **Diretivas** começando com `.`: `.source`, `.linedefined`, `.lastlinedefined`, `.numparams`, `.is_vararg`, `.maxstacksize`, `.upval`, `.local vN` / `.end local`, `.line N`, `.func F<n>` … `.end ; F<n>`.
  - **Opcodes** com registradores nomeados: `MOVE`, `LOADK v9 "Hello world"` (constantes inline em vez de índices;
    `LOADKX+EXTRAARG` aparece como `LOADK`), `CALL v2..v5 v2..v2` (faixas de registradores), `CLOSURE v2 F0`
    (protótipos por nome), `JMP :goto_465 ; +4 ↓` com rótulos `:goto_465`, mais `IDIV/BNOT/BAND/BOR/BXOR/SHL/SHR`.
  - **Comentários** com `;`.
  - Código inválido é preservado: `CONST[A]`, `GOTO[A]`, `FUNC[A]`, `OP[A] 0xB` (instrução bruta em hex), para
    remontar byte a byte o que não é interpretável.
- Fluxo: "Executar script → Mais → Desmontar" gera `.lasm`; editar; executar o `.lasm` → GG monta e grava
  `<arquivo>.<ts>.lua` binário (não executa) (Script.java:5496-5517).
- Avisos oficiais: compatibilidade de `.lasm` entre versões não é garantida; montar+desmontar pode mudar bytes;
  maiúsculas e ordem das diretivas importam.

### 4.2 Configurações (config.html) — o que revelam da implementação

- *Freeze interval* / *Saved list updates interval*: congelamento = **reescrita periódica** (polling), não hook.
- *Fast freeze*: modo mais rápido "que não funciona para toda memória" [H: escrita via `/proc/pid/mem` vs ptrace].
- *Deep read*: tenta "todos os métodos" de leitura quando falha.
- *System calls mode*, *waitpid mode*: workarounds de firmware para ptrace/waitpid (busca infinita com SELinux ruim).
- *Bypass mode for ptrace protection*: restore / nothing / freeze (o que fazer após desconectar a proteção).
- *Use root in virtual space*, *Prevent unload* (3 níveis), *Data in the RAM*, *Temporary path* (resultados de busca
  em arquivo temporário), *Hide GameGuardian from the game* (opções 2,3,4 deixam a busca mais lenta).

### 4.3 FAQ / help — pontos que valem ouro para o nosso app

- Valor alterado "volta": é cópia de exibição (decifrada); procure o valor cifrado, use fuzzy, ou é servidor.
- Teste de sanidade: jogos sem proteção ("Hill Climb Racing", "Tap Counter").
- Speedhack não funciona em timers Java no ART (Android 5+) nem em x86 sem libs x86; escolha de "timers verdes".
- Tempo: buscar como dias/horas/s, ms/ns (Dword/Qword) ou timestamp Unix com intervalo.
- `!`/`#` antes do processo = processo rastreado/rastreador (ptrace) — indício de proteção (SecNeo → PTRACE_ATTACH falha).
- Endereço "vivo": escreva valores distintos, deixe o jogo rodar, releia (FAQ 34).
- Zero resultados ≠ valor ausente: regiões vazias e Zygote são puladas por padrão; regiões não selecionadas (FAQ 35).
- Fill/increment para achar o item certo; "Revert and remove" para não crashar.
- Busca não alinhada / big-endian é feita por script oficial (não nativo).
- Calculadora: `= expr` em qualquer campo, em Lua, locale inglês.
- Amostras oficiais (official_lua_samples.html): Chainer (cadeias de ponteiros), LP2lua, base+offset, compilador de
  script, busca/troca de texto/AoB, busca não alinhada.

## 5. Lições para o nosso app

### 5.1 Plano de compatibilidade de API (para rodar scripts GG existentes de jogos single-player)

1. **Mesmos nomes, assinaturas, padrões e valores de constantes** (§1.2), inclusive os esquisitos:
   `PROT_READ=2/PROT_WRITE=1`, `SIGN_FUZZY_* == SIGN_*`, `REGION_OTHER=-2080896`, aliases ocultos
   (`SIGN_INEQUAL/SMALLER/LARGER`, `getSelectedPackage`, `getResultCount`), troca de argumentos legada de
   `searchFuzzy`, `VERSION/BUILD` configuráveis para que `gg.require('101.4', 16155)` passe.
2. **Mesma convenção de erro**: `true | "mensagem"` para falhas de operação; erro Lua só para argumento inválido.
3. **Mesmo parser de texto de busca** (§1.4) — é a parte que mais quebra scripts. Criar uma suíte de testes com as
   strings dos exemplos de `classgg.html` (searchNumber/editAll/setValues) e da `help.html`.
4. **Semântica de estado**: `searchNumber` refina se há resultados; `editAll` exige `getResults` antes;
   `setRanges` é restaurado ao fim salvo `skipRestoreState`; resultados vivem fora do script (persistem na UI).
5. **Itens** como tabelas com as chaves `address,value,flags[,name,freeze,freezeType,freezeFrom,freezeTo]`;
   `TYPE_XOR` = valor ^ endereço; endereços 32-bit mascarados.
6. **Bytecode**: aceitar Lua 5.2 + tag de constante `-2` + opcodes 5.3 extras para rodar `.lua` binários do GG;
   aceitar BOM; detectar `.lasm` pelo cabeçalho. (Implementação de referência: `luaj/a.java`, `luaj/g.java`.)
7. **Semântica numérica**: o GG usa "1º operando define o tipo". Oferecer modo `gg_compat_math` (padrão ligado
   para scripts com `gg.require` ≤ 101.x) e modo Lua 5.4 padrão para scripts novos.
8. Locale: scripts sempre em inglês; `numberToLocale/FromLocale` só para UI.

### 5.2 Melhorias sobre o GG

- **Interrupção confiável**: hook de contagem de instruções (como `lua_sethook` com `LUA_MASKCOUNT`) para parar
  laços puros; timeout opcional por script.
- **Sem round-trip na UI thread** para leitura/escrita/busca: chamar o backend direto da thread do script; só
  diálogos vão à UI. Ganho grande em laços de `getValues/setValues`.
- **Async real/corrotinas**: incluir `coroutine` (o GG não tem) e eventos (`gg.onUiButton(fn)`) em vez de polling.
- **Sandbox por allow-list e explícito**: em vez de "arquivo vazio silencioso", erro claro; permissões declaradas
  pelo script (rede, diretórios) e mostradas antes de rodar; manter a checagem `readlink(/proc/self/fd)` (boa ideia)
  e limites de arquivos/bytes.
- **Rede**: manter consentimento por execução, adicionar allow-list de domínios e log das URLs acessadas.
- **Depuração de primeira classe**: manter as três boas ideias do GG — log de chamadas `gg.*`, captura de chunks de
  `load()` e disassembler — e adicionar breakpoints/inspeção de variáveis.
- **Gravador de macro → script** (o `c2` do GG) como recurso central, gerando código legível com constantes nomeadas.
- **Resultados em streaming / userdata**: `getResults` sem materializar milhões de tabelas; iterador paginado.
- **Regiões**: expor a linha bruta do `/proc/pid/maps` e permitir filtros por nome/permissão, além das siglas;
  documentar a migração Scudo → `C_ALLOC`.
- **Não reproduzir**: ofuscação de constantes, sabotagem silenciosa (`gg.searchNumber = nil`), botões trocados
  aleatoriamente. Num app aberto isso só atrapalha usuários legítimos.
- **Escopo ético**: foco em jogos single-player/offline; não implementar "esconder do anti-cheat"/bypass de proteção.
